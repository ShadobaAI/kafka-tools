# ELK — история обмена и технологический журнал

[← Все инструменты](../README.md)

> Команды выполняются из каталога `tools/elk`. Пути к файлам в описаниях указаны относительно корня репозитория `tools`, если не оговорено иное.

ELK-стек для централизованного логирования истории обмена адаптера.

```
docker compose up -d
```

| Сервис | Адрес |
|--------|-------|
| Elasticsearch | http://localhost:9200 |
| Kibana | http://localhost:5601 |
| Logstash (HTTP input) | http://localhost:8082 |
| Elasticsearch MCP (Streamable HTTP) | http://localhost:8080/mcp |

Конфигурация входа HTTP находится в [logstash.conf](config/logstash.conf).

MCP-сервер подключается к Elasticsearch через сеть Compose. Укажите адрес из таблицы в MCP-клиенте; проверка доступности — `http://localhost:8080/ping` (ответ `pong`). На хосте порт MCP доступен только через `127.0.0.1`. В этой конфигурации Elasticsearch и MCP работают без аутентификации.

[Elasticsearch MCP Server](https://github.com/elastic/mcp-server-elasticsearch) объявлен устаревшим и получает только критические обновления безопасности.

## Импорт технологического журнала 1С

Пример настроек технологического журнала платформы 1С находится в [ones/logcfg.xml](../ones/logcfg.xml).

Скрипт [import-1c-logs.py](import-1c-logs.py) работает на Python 3 со стандартной библиотекой. Он рекурсивно находит `.log` в `C:\kfk`, читает JSON по одной записи на строку и отправляет документы пакетами через REST API Elasticsearch. Свойства JSON становятся полями документа, а числа передаются в исходном представлении.

Встроенная справка на русском открывается командой `python .\import-1c-logs.py --help`.

Имя индекса состоит из части имени каталога перед `_<PID>`, значения `--prefix` и даты `YYYYMMDD` из имени файла `YYMMDDHH.log`. Для `rphost_11972\26111709.log` с `--prefix=-kfk-` получится `rphost-kfk-20261117`. Разделители задаются в `--prefix`.

Проверить первые пять записей и рассчитанные имена индексов без сетевых запросов можно так.

```powershell
python .\import-1c-logs.py --prefix=-kfk- --dry-run --limit 5
```

При запуске без `--dry-run` и `--limit` скрипт загружает записи из всех найденных файлов.

```powershell
python .\import-1c-logs.py --prefix=-kfk-
```

Параметры `--log-dir` и `--url` задают каталог логов и REST-адрес Elasticsearch. Идентификатор записи учитывает путь к файлу, номер строки и её содержимое. Повторный импорт пропускает неизменившиеся строки, загруженные с тем же префиксом этой версией скрипта. У записей, загруженных версией с идентификаторами по пути и номеру строки, другие `_id`.

Один пакет содержит до 1000 записей и обычно занимает до 5 МиБ. Запись крупнее 5 МиБ отправляется отдельно, верхний предел запроса составляет 100 МиБ. При ответе `429` скрипт повторяет отправку отклонённых записей до трёх раз с увеличивающейся задержкой. Ошибки обхода каталогов и превышение предельного размера завершают импорт с диагностикой.

## Резервное копирование и восстановление

[backup.ps1](backup.ps1) сохраняет том Elasticsearch в `C:\docker-backups\elk\elastic_data.tar`.

```powershell
.\backup.ps1
```

[restore.ps1](restore.ps1) заменяет содержимое тома данными из этого архива. Для восстановления проверьте наличие архива и остановите Elasticsearch, сохранив его контейнер.

```powershell
docker compose stop elasticsearch
.\restore.ps1
docker compose start elasticsearch
```
