# OpenViking и Ollama

Два независимых набора Bash-скриптов для новой установки: `ollama/start.sh` запускается на Windows-машине с NVIDIA GPU, а `openviking/start.sh` и `openviking/update.sh` — на машине с репозиториями Kafka. Все настройки находятся в самих `.sh`. Файлы можно запускать двойным щелчком, если `.sh` в Windows связан с Git Bash; иначе откройте их через Git Bash. Скрипты не принимают аргументов и в конце ждут Enter.

## Подготовка

На обеих машинах нужны Git Bash и Docker Desktop с Linux-контейнерами и Compose. На GPU-машине нужны NVIDIA-драйвер и поддержка GPU в Docker Desktop. На машине OpenViking дополнительно нужны доступные в Git Bash команды `git`, `curl`, `jq` и `openssl`; `jq` установите отдельно и добавьте в PATH Git Bash. Доступ к каталогу `adapter/adapter` и его Git-объектам обязателен. Запускайте скрипты с правами обычного пользователя, а не из песочницы, запрещающей этот доступ.

Скрипт Ollama публикует порт 11434 на всех сетевых интерфейсах без аутентификации. Ограничьте доступ к нему в брандмауэре только машиной OpenViking. Адрес по умолчанию — `http://iA11:11434` в `openviking/common.sh`; измените его, если GPU-хост доступен под другим именем. DNS-имя должно разрешаться и на хосте, и внутри Docker-контейнера OpenViking.

## Первый запуск

1. Скопируйте каталог `ollama` на GPU-машину и запустите `start.sh`. Он создаст volume `ollama-models`, запустит контейнер и скачает отсутствующие `qwen3-embedding:0.6b` и `qwen3.5:4b`. Потребуются интернет и место под образы и модели. Проверяйте фактическое использование GPU через `docker exec ollama ollama ps` во время работы модели.
2. Запустите `openviking/start.sh`. Он скачает образ OpenViking `v0.5.1` при отсутствии, создаст volume `kafka-openviking_openviking-data`, конфигурацию и ключи, запустит сервер и проверит его готовность. Если загрузка из GHCR не удалась, скрипт проверит digest официального GHCR-манифеста и скачает образ по нему из Docker Hub; без доступа к официальному манифесту он остановится. Повторный запуск использует сохранённый digest. API доступен только на `127.0.0.1:1933`.
3. Запустите `openviking/update.sh`. Он загрузит Markdown-файлы из `adapter/adapter/docs` на текущем закоммиченном `HEAD` в `viking://resources/kafka-git/kafka-adapter/docs`. Неотслеживаемые и незакоммиченные изменения, изображения и другие файлы не индексируются.

Повторный запуск `update.sh` загружает только изменившиеся документы и проверяет наличие остальных. Он останавливается, если изменились digest моделей или версия сервера. Удалённые в Git документы перечисляются и удаляются из базы только после ввода `yes`. При изменении HEAD во время обновления или ошибке после начала записи состояние помечается незавершённым. Скрипт может продолжить прерванную первую загрузку, только если сохранённого состояния ещё нет, хранилище ресурсов пусто и очередь обработки дважды подтверждена как свободная; прежний маркер сохраняется. В остальных случаях требуется ручная проверка, автоматического удаления базы нет.

Состояние и секреты находятся вне репозитория: `$HOME/.openviking` в Git Bash, обычно `%USERPROFILE%\.openviking` в Windows. Клиентский ключ находится в `tenant.curl`, корневой — в `root.curl` и `ov.conf`. Файл `tenant.curl` можно перенести как секрет для доступа к тому же аккаунту; он не содержит адрес сервера. API по умолчанию доступен только локально. Сохраняйте каталог состояния вместе с Docker volume.

Для другого расположения измените константу `STATE_DIR` в `openviking/common.sh`, например на `"$HOME/openviking-standalone"` или `"/c/openviking-standalone"`. Перед переносом остановите все запуски `start.sh` и `update.sh`, перенесите **весь** каталог состояния в новое место и затем запустите `start.sh`: он обновит путь монтирования конфигурации в Compose. Docker volume при этом сохраняется. Не размещайте каталог с ключами и состоянием в Git-репозитории.

Если volume удалён и сервер вернул 401 для старого клиентского ключа, `start.sh` проверяет список аккаунтов. Если аккаунта `kafka` нет, скрипт создаёт его заново, сохраняет старый файл ключа отдельно и записывает новый `tenant.curl`. Другие клиенты со старым ключом нужно перенастроить. Если аккаунт уже существует или его состояние нельзя проверить, скрипт остановится и не заменит ключ. Сохранённое состояние индекса автоматически не удаляется.

Каталог `sync.lock` означает выполняющееся или аварийно завершившееся обновление; после сбоя его можно удалить только убедившись, что других обновлений нет и обработка на сервере закончилась. Маркер `dirty` означает незавершённые изменения; его нельзя просто удалять без проверки согласованности базы и состояния. Содержимое ключей и конфигурации не публикуйте.

Скрипт закреплён на версии 0.5.1; автоматическое обновление OpenViking и миграция базы не реализованы. Не меняйте версию образа или модели для существующей базы без отдельной проверки совместимости индекса. Контейнеры и данные скрипты не удаляют. Для диагностики используйте `docker compose -f "$HOME/.openviking/compose.yaml" logs --tail 100` в Git Bash и `docker logs --tail 100 ollama` на GPU-машине.
