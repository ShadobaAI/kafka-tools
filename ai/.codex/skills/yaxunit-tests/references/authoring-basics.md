# YAxUnit Authoring Basics

Read this once when creating a test common module or materially rewriting its data setup or database assertions. These are stable defaults; use the installed YAxUnit core only for exact unknown signatures, capabilities, or incompatible runtime behavior.

- Keep `ИсполняемыеСценарии()` declarative: register a named set through `ЮТТесты.ДобавитьТестовыйНабор(...)`, then its tests/parameters through the installed `ДобавитьТест(...)`/parameter API. Use `ВТранзакции()` for server tests only when its real scope fits the side effects.
- Create common-module top-level regions according to the std455 baseline. Nest functional grouping inside the applicable standard region; do not replace it with arbitrary top-level regions.
- Assert database/register presence, absence, count, fields, or row sets through `ЮТест.ОжидаетЧтоТаблицаБазы(...)` and installed specialized predicates such as `ЧтоТаблица`/`СодержитЗаписи` by default. Use generic `ОжидаетЧто(...)` for ordinary values; a query remains valid when it is itself the tested API input. Confirm an unfamiliar chain/signature against the installed core.
- Use `ЮТест.Данные()` as the public data entry point. Prefer a shared semantic project fixture when it already represents the needed domain data; otherwise choose the narrowest suitable public operation for local scenario data, and use low-level platform creation only as a justified fallback.
- Use `СоздатьЭлемент(...)`, `СоздатьДокумент(...)`, or `СоздатьГруппу(...)` for a minimal object/reference; `КонструкторОбъекта(...)` for controlled attributes or write/post behavior; `КонструкторДвижений(...)` for supported movements/register records; and `КонструкторОбъектаXDTO(...)` for XDTO data. Set behavior-material values explicitly. Generate incidental values through the suitable `Фикция`, `ФикцияРеквизитов`, `ФикцияОбязательныхПолей`, `ФикцияНезаполненных`, `ФикцияНезаполненныхИсключая`, or public random-value generator confirmed in the installed core.
- Set an exact deterministic fixture value only when it affects the scenario's contract or observable behavior, and keep it valid for the declared type and domain contract. Generate incidental fields through the suitable public YAxUnit data operation; generated data must not make expected behavior nondeterministic.
