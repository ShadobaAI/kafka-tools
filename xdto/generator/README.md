# Генерация XSD

[← Инструменты AsyncAPI](../README.md)

> Команды выполняются из корня репозитория `tools`.


Генератор создаёт проверенную XSD из `components.schemas` в YAML для произвольного XDTO-формата Адаптера Kafka. Каналы и остальные разделы AsyncAPI необязательны. [Требования к YAML](https://github.com/ShadobaAI/kafka-adapter/blob/main/docs/project/yaml-requirements-for-xdto.md) и [описание генерации](https://github.com/ShadobaAI/kafka-adapter/blob/main/docs/project/xsd-generation.md) определяют поддерживаемый профиль.

### Окружение

Python 3.10 или новее. Зависимости зафиксированы в `xdto/generator/requirements.txt`; проверенное окружение — Python 3.12, PyYAML 6.0.3 и lxml 6.1.1.

```powershell
python -m venv .\xdto\.venv
.\xdto\.venv\Scripts\python.exe -m pip install -r .\xdto\generator\requirements.txt
```

### Использование

```powershell
.\xdto\.venv\Scripts\python.exe .\xdto\generator\asyncapi2xsd.py <input.yaml> <output.xsd> -n <namespace> [--prefix <prefix>] [--suffix <suffix>]
```

| Аргумент | Обязательность | Назначение |
| --- | --- | --- |
| `input` | Обязателен. | YAML с непустым `components.schemas`. |
| `output` | Обязателен. | Путь результирующей XSD. |
| `-n`, `--namespace` | Обязателен. | Собственный абсолютный URI пространства имён пакета. |
| `--prefix` | Необязателен. | Начальная часть адреса топика для удаления при именовании типа. |
| `--suffix` | Необязателен. | Конечная часть адреса топика для удаления при именовании типа. |

Пример поддерживаемой модели: [supported-example.yaml](supported-example.yaml).

```powershell
.\xdto\.venv\Scripts\python.exe .\xdto\generator\asyncapi2xsd.py .\xdto\generator\supported-example.yaml .\out.xsd -n http://example.com/xdto
```

Адрес `crm.order.changed` с `--prefix crm.` и `--suffix .changed` даёт тип `Order`. При отсутствии разрешаемой связи с каналом имя берётся из ключа схемы. Все сообщения канала учитываются, неоднозначность и коллизии имён вызывают ошибку. Алиас переиспользует имя целевого типа.

### Поддерживаемая модель

| YAML | Результат |
| --- | --- |
| `string` | Именованный тип на основе `xs:string`. |
| `string`, `format: uuid` | Общий тип `UUID` с длиной 36 и шаблоном идентификатора. |
| `string`, `format: date`, `date-time`, `time` | Тип на основе `xs:date`, `xs:dateTime`, `xs:time`. |
| `integer`, без формата / `int32` / `int64` | Тип на основе `xs:integer` / `xs:int` / `xs:long`. |
| `number`, без формата / `float` / `double` | Тип на основе `xs:decimal` / `xs:float` / `xs:double`. |
| `boolean` | Тип на основе `xs:boolean`. |
| `object` | Именованный `complexType` с элементными свойствами и одной `sequence`. |
| Локальный `$ref` или алиас | Переиспользование целевого типа без изменения его вида. |
| `enum` | Ограниченный простой тип с кодами перечисления. |
| Табличный контейнер | Один объект с одним повторяющимся свойством объектных строк; дополнительная обёртка не создаётся. |

Необязательное одиночное поле получает `minOccurs=0`, обязательное — `1`; `nillable=false` в обоих случаях. `required` не задаёт непустоту значения.

Массив объектных строк допускается только в объекте с единственным свойством. Для строки `minItems=0` поле не включается в `required`; для `minItems>0` включается. Верхняя граница отсутствует или больше 1. Иные сочетания присутствия и количества отклоняются как непредставимые в данном профиле.

Inline вложенная группа получает имя `{Родитель}.ОбщиеСвойства.{Поле}`. Общая схема группы, используемая по ссылке, должна содержать `ОбщиеСвойства` в результирующем имени. Тип строки таблицы этого соглашения не требует.

Поддерживаются строковые границы длины и переносимый regex-профиль, числовые границы и точно представимый `multipleOf`: `10^-N` для decimal, `1` для integer. Числовые значения загружаются с сохранением десятичной точности. Возможности чисел дополнительно ограничены реализацией XMLSchema в libxml; непредставимый результат вызывает ошибку.

Regex-профиль: ASCII-литералы, положительные ASCII-классы и диапазоны, `\d`, экранированные специальные символы и обычные повторения. Поиск подстроки преобразуется в соответствующий XSD-шаблон. Якоря, wildcard `.`, группы, альтернативы, lookaround, backreference и ленивые повторения отклоняются.

`title` и `description` сохраняются в `xs:documentation`. `default` и `examples` проверяются как значения схемы, но не записываются как default/fixed XSD. Аннотации `deprecated` и `x-*` не становятся данными сообщения; `x-enumNames` и `x-topics` необязательны.

### Явно неподдерживаемые формы

- Корневые схемы массивов и простые списки: нет согласованного двунаправленного контракта стандартной конвертации.
- Массивы с `maxItems` 0 или 1, вложенные массивы и массивные поля среди нескольких обычных реквизитов.
- `null`, `nullable`, списки типов, `allOf`, `oneOf`, `anyOf`, внешние ссылки и структурные ограничения рядом с `$ref`.
- `additionalProperties`, `patternProperties`, условные схемы и неизвестные проверочные ключи.
- Специальное поле `AdditionalInfo`, boolean enum и enum/custom facets для UUID.

Объектная модель переносит объявленные `properties`. Отсутствие `additionalProperties` не является явным запретом дополнительных полей исходной JSON Schema; полная эквивалентность произвольной JSON Schema и XSD не заявляется.

Старые `asyncapi_example.yaml`, `kfk-test.yaml` и `kfk-unit.yaml` содержат формы за пределами этого профиля. Они находятся в [examples/legacy](../examples/legacy/README.md) и остаются материалами других инструментов и не являются готовыми входными примерами новой версии генератора. Их XSD не редактируются вручную.

### Ошибки и результат

Успех: код завершения `0`, проверенная XSD в выходном файле. Ошибка входа или файловой системы: код `2`, категория, путь определения и причина в stderr. Невалидная или частичная схема не публикуется. Выходной файл заменяется атомарно после проверки; при ошибке прежний файл сохраняется. Входной и выходной пути должны различаться.

Вход ограничен 10 MiB, 100 000 узлами и глубиной 128. Раскрытие ссылок ограничено 100 вложенными определениями; regex — 4096 символами и числовыми границами повторения до 1000; числовая запись — 1000 цифрами и модулем десятичного показателя до 1000. Дубли ключей, YAML merge и рекурсивные YAML-структуры отклоняются.

### Внутренний интерфейс

`asyncapi2xsd.generate_xsd(document, namespace, prefix=..., suffix=...)` возвращает проверенные UTF-8 байты без записи файла. Документ содержит JSON-совместимые значения; дробные числа представлены `decimal.Decimal`. `convert_file(...)` выполняет загрузку и атомарную запись. `SchemaError` содержит категорию и путь входного определения.

Вся реализация находится в одном файле `asyncapi2xsd.py`. Внутри него отдельно описаны типизированная модель, загрузка YAML, значения и фасеты, компиляция схем, выпуск XSD и CLI. CLI не содержит правил преобразования.

### Проверки генератора

```powershell
.\xdto\.venv\Scripts\python.exe -m unittest discover -s .\xdto\generator -p test_generator.py -v
.\xdto\.venv\Scripts\python.exe -m compileall -q .\xdto\generator\asyncapi2xsd.py .\xdto\generator\test_generator.py
```

Тесты проверяют модель, положительные и отрицательные XML-экземпляры, CLI и сохранение результата при ошибке. Проверка XML не заменяет интеграционную проверку XDTO → JSON на платформе 1С.
