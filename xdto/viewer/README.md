# Просмотр в Confluence

[← Инструменты AsyncAPI](../README.md)

> Команды выполняются из корня репозитория `tools`.

Самодостаточный HTML-визуализатор AsyncAPI-спецификации для HTML macro Confluence. Загружает attachment `asyncapi.yaml` с текущей страницы без фиксации версии attachment и не зависит от внешнего CDN или backend-приложения.

Возможности:

- обязательный выбор Kafka-топика с сохранением адреса в URL hash;
- компактная информация о топике, формате и количестве полей;
- табличное представление properties с поддержкой вложенных объектов и массивов;
- разрешение локальных `$ref`, включая enum, `allOf` и защиту от циклов;
- отображение `x-configuration-kind` рядом с `title` у вложенных полей;
- настройка колонок таблицы по полям, создаваемым `кфкРаботаСоСпецификациями.СформироватьAsyncAPI`, с кнопкой «По умолчанию»; начальный набор: Property / Title, Description, Type, Format / Enum, x-topics, Min / Max;
- отображение `x-topics`, ограничений, examples и пользовательских `x-*`;
- поиск внутри выбранного топика и фильтры `Required` / `Deprecated`;
- раскрытие и сворачивание вложенных полей;
- экспорт текущего отфильтрованного представления в CSV с выбранными колонками и UTF-8 BOM.

### Подключение к Confluence

1. Прикрепить к странице файл с точным именем `asyncapi.yaml`.
2. Поместить содержимое [`viewer.html`](viewer.html) в HTML macro на этой же странице.
3. Если `pageId` не определяется из контекста Confluence автоматически, указать его в константе `PAGE_ID` внутри `viewer.html`.

При обновлении спецификации достаточно заменить attachment; изменять HTML macro не требуется.

### Локальный просмотр

Из корня репозитория `tools` выполни в PowerShell:

```powershell
python -m http.server 8000 --directory .\xdto\viewer
```

Открой <http://localhost:8000/viewer.html>. Остановить сервер можно клавишами `Ctrl+C`. Для другой спецификации положи её в `xdto/viewer/download/attachments/1/asyncapi.yaml`: viewer запрашивает именно это имя при `PAGE_ID = '1'`. Прямое открытие `viewer.html` через `file://` не подходит, поскольку viewer загружает YAML запросом `fetch`.

Каталог `download/attachments/1` сохраняется в Git через `.gitkeep`; `.gitkeep` не является спецификацией.
